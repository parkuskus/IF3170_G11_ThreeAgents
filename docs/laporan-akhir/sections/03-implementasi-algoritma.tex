\section{Representasi State}

State merepresentasikan satu konfigurasi pemuatan paket pada sebuah truk. Implementasi menyimpan data paket dan truk secara terpisah, lalu menghubungkan setiap paket dengan posisinya melalui pemetaan dari ID paket ke objek penempatan. Nilai penempatan \texttt{None} menandakan paket berada di luar truk, sehingga state tetap mencatat seluruh paket, baik yang dimuat maupun tidak.

Objek \texttt{Package} menyimpan ID, dimensi awal, nilai, berat, status mudah pecah, dan ETA. Dimensi disimpan sebagai tiga bilangan bulat, sedangkan orientasi adalah permutasi indeks dimensi yang menentukan urutan ukuran setelah rotasi. Ada enam kemungkinan orientasi, sesuai seluruh permutasi indeks tiga dimensi. Objek \texttt{Truck} menyimpan dimensi ruang muat serta kapasitas berat maksimum. Objek \texttt{Placement} menggabungkan koordinat sudut paket, dimensi setelah orientasi diterapkan, dan orientasinya. Kode~\ref{lst:state-model} memperlihatkan struktur data inti dari \texttt{src/model.py}; pemeriksaan validasi dihilangkan dari cuplikan agar fokus pada field representasinya.

Secara matematis, satu state dituliskan sebagai $S=(P,T,\phi)$, dengan $P=(p_1,\ldots,p_n)$ sebagai kumpulan paket, $T=(\mathbf{L},C)$ sebagai truk berdimensi $\mathbf{L}$ dan berkapasitas maksimum $C$, serta $\phi$ sebagai pemetaan penempatan. Jika paket $p_i$ memiliki ID $\operatorname{id}_i$ dan dimensi $\mathbf{d}_i$, maka representasinya adalah

\begin{equation}
    \begin{aligned}
        I                    & = \{\operatorname{id}_1,\ldots,\operatorname{id}_n\}, \\
        \phi                 & : I \longrightarrow \{\bot\} \cup
        \left\{(\mathbf{x}_i,\mathbf{d}_i^{\pi_i},\pi_i)\;\middle|\;
        \mathbf{x}_i \in \mathbb{Z}_{\geq 0}^{3},\; \pi_i \in S_3\right\},           \\
        \mathbf{d}_i^{\pi_i} & = (d_{i,\pi_i(1)},d_{i,\pi_i(2)},d_{i,\pi_i(3)}).
    \end{aligned}
    \label{eq:state-representation}
\end{equation}

Di sini $\bot$ menyatakan paket tidak dimuat, $\mathbf{x}_i$ adalah koordinat sudut paket di dalam truk, dan $S_3$ adalah himpunan enam permutasi sumbu yang merepresentasikan orientasi. Domain $I$ memastikan setiap paket memiliki tepat satu entri penempatan. Persamaan~\ref{eq:state-representation} menjelaskan bentuk representasi; batas ruang, kapasitas, dan batasan fisik lainnya menentukan apakah state tersebut layak.

Pemetaan \texttt{placements} harus memiliki tepat satu entri untuk setiap ID paket. Konstruktor \texttt{State} memeriksa keunikan ID, kelengkapan kunci pemetaan, dan kecocokan dimensi hasil orientasi dengan dimensi paket. Fungsi objektif state menjumlahkan nilai paket yang memiliki penempatan, sehingga paket di luar truk tidak berkontribusi terhadap nilai solusi.

Contoh berikut menunjukkan sebuah paket di dalam truk dan satu paket yang tidak dimuat. Koordinat menggunakan urutan sumbu $x$, $y$, dan $z$, sedangkan koordinat $(0,0,0)$ menandakan sudut bawah paket berada di titik asal ruang muat.

\end{lstlisting}

\section{\textit{Constraint} Permasalahan}

State layak apabila seluruh syarat berikut terpenuhi. Misalkan $I^+=\{i\in I\mid\phi(i)\neq\bot\}$ adalah himpunan ID paket yang dimuat. Untuk setiap $i\in I^+$, penempatannya ditulis sebagai $\phi(i)=(\mathbf{x}_i,\mathbf{d}_i,\pi_i)$, dengan $\mathbf{x}_i=(x_i,y_i,z_i)$ sebagai koordinat dan $\mathbf{d}_i=(w_i,d_i,h_i)$ sebagai dimensi setelah rotasi. Syarat kelayakan dituliskan dalam enumerasi berikut.

\begin{enumerate}
    \renewcommand{\labelenumi}{(\arabic{enumi})}
    \item Setiap paket harus seluruhnya berada di dalam ruang muat truk:
          \begin{equation*}
              \mathbf{0}\leq\mathbf{x}_i,\qquad \mathbf{x}_i+\mathbf{d}_i\leq\mathbf{L},\qquad \forall i\in I^+.
          \end{equation*}

    \item Setiap pasangan paket harus terpisah pada setidaknya satu sumbu, sehingga keduanya tidak saling bertumpang tindih. Di sini $d_{i,k}$ adalah ukuran paket $i$ pada sumbu $k$:
          \begin{equation*}
              \exists k\in\{x,y,z\}:\quad x_{i,k}+d_{i,k}\leq x_{j,k}\ \lor\ x_{j,k}+d_{j,k}\leq x_{i,k},\qquad \forall i,j\in I^+,\ i\neq j.
          \end{equation*}

    \item Jumlah berat semua paket yang dimuat tidak boleh melebihi kapasitas truk $C$. Simbol $w_i^{\text{paket}}$ menyatakan berat paket, bukan ukuran pada sumbu $x$:
          \begin{equation*}
              \sum_{i\in I^+}w_i^{\text{paket}}\leq C.
          \end{equation*}

    \item Paket yang berada di atas lantai truk harus ditopang oleh setidaknya satu paket lain yang tidak rapuh. Bagian atas paket penopang harus sejajar dengan dasar paket yang ditopang, dan proyeksi alas keduanya harus beririsan:
          \begin{equation*}
              \begin{aligned}
                  z_i>0 & \Rightarrow \exists j\in I^+,\ j\neq i:                                                                       \\
                        & z_j+h_j=z_i,\quad \neg\operatorname{rapuh}(j),\quad \operatorname{overlap}_{xy}(i,j),\qquad \forall i\in I^+.
              \end{aligned}
          \end{equation*}
\end{enumerate}

Predikat $\operatorname{overlap}_{xy}$ bernilai benar ketika proyeksi alas dua paket beririsan dengan luas positif. Karena itu, implementasi tidak menganggap kontak yang hanya terjadi pada tepi atau satu titik sebagai dukungan, meskipun spesifikasi menyebut dukungan pada setidaknya satu titik alas. Paket di lantai truk ($z_i=0$) tidak memerlukan paket penopang. Kode~\ref{lst:state-validation} menunjukkan pemeriksaan yang dipakai oleh \texttt{validate\_state}; fungsi bantu irisan satu dimensi dan alas juga disertakan.

\begin{lstlisting}[caption={Validasi batas ruang, tabrakan, kapasitas, dan dukungan},label={lst:state-validation}]
from itertools import combinations

from src.model import Package, Placement, State

def _overlap_1d(start_a, size_a, start_b, size_b):
    return start_a < start_b + size_b and start_b < start_a + size_a

def _overlap_xy(a, b):
    return (
        _overlap_1d(a.coordinate[0], a.oriented_dimensions[0],
                    b.coordinate[0], b.oriented_dimensions[0])
        and _overlap_1d(a.coordinate[1], a.oriented_dimensions[1],
                        b.coordinate[1], b.oriented_dimensions[1])
    )

def _overlap_3d(a, b):
    return _overlap_xy(a, b) and _overlap_1d(
        a.coordinate[2], a.oriented_dimensions[2],
        b.coordinate[2], b.oriented_dimensions[2]
    )

def validate_state(state):
    errors = []
    placed = [
        (package, placement)
        for package in state.packages
        if (placement := state.placements[package.id]) is not None
    ]

    for package, placement in placed:
        if any(
            position + size > limit
            for position, size, limit in zip(
                placement.coordinate, placement.oriented_dimensions,
                state.truck.dimensions
            )
        ):
            errors.append(f"package {package.id!r} is outside the truck")

    for (package_a, placement_a), (package_b, placement_b) in combinations(placed, 2):
        if _overlap_3d(placement_a, placement_b):
            errors.append(f"packages {package_a.id!r} and {package_b.id!r} overlap")

    total_weight = sum(package.weight for package, _ in placed)
    if total_weight > state.truck.max_capacity:
        errors.append("truck capacity is exceeded")

    for package, placement in placed:
        if placement.coordinate[2] == 0:
            continue
        supported = any(
            not support_package.fragile
            and support_placement.coordinate[2]
                + support_placement.oriented_dimensions[2]
                == placement.coordinate[2]
            and _overlap_xy(placement, support_placement)
            for support_package, support_placement in placed
            if support_package.id != package.id
        )
        if not supported:
            errors.append(f"package {package.id!r} is unsupported")

    return errors
\end{lstlisting}

\section{\textit{Successor Function}}

Fungsi suksesor membangkitkan kandidat dengan menerapkan salah satu operator berikut secara acak:

\begin{enumerate}
    \renewcommand{\labelenumi}{(\arabic{enumi})}
    \item \textit{Move} memilih satu paket. Jika paket sudah dimuat, orientasinya dipertahankan; jika masih di luar truk, orientasi dipilih secara acak. Paket kemudian ditempatkan pada koordinat baru yang masih berada dalam rentang truk.
    \item \textit{Rotate} memilih satu paket yang sedang dimuat, lalu menukar dua sumbu orientasinya (rotasi 90 derajat) tanpa mengubah koordinat paket.
    \item \textit{Swap} memilih dua paket dan menukar status pemuatan atau posisi keduanya. Dimensi penempatan disesuaikan dengan ukuran dan orientasi masing-masing paket.
\end{enumerate}

Operator \textit{swap} hanya tersedia jika state memiliki setidaknya dua paket. Misalkan $\mathcal{O}(S)$ adalah himpunan operator yang tersedia pada state $S$. Himpunan suksesor layak didefinisikan sebagai

\begin{equation}
    N(S)=\{S'\mid S'=o(S),\ o\in\mathcal{O}(S),\ S'\neq S,\ \operatorname{validate}(S')=\emptyset\}.
    \label{eq:successor-function}
\end{equation}

Pada operator \textit{move}, ketinggian dipilih dari lantai truk atau permukaan atas paket lain. Setiap kandidat harus berbeda dari state asal dan lolos validasi. Implementasi mencoba paling banyak 100 kandidat, lalu mengembalikan kandidat layak pertama; jika tidak ada paket atau tidak ditemukan kandidat yang layak, fungsi mengembalikan state asal. Cuplikan~\ref{lst:random-neighbor} memperlihatkan pemilihan operator dan penyaringan tersebut.

\begin{lstlisting}[caption={Pemilihan kandidat suksesor yang valid},label={lst:random-neighbor}]
from random import Random

def random_neighbor(state, rng=None, max_attempts=100):
    if max_attempts < 1 or not state.packages:
        return state
    rng = rng or Random()
    operations = [_move_candidate, _rotate_candidate]
    if len(state.packages) > 1:
        operations.append(_swap_candidate)

    for _ in range(max_attempts):
        candidate = rng.choice(operations)(state, rng)
        if candidate is not state and _valid(candidate):
            return candidate
    return state
\end{lstlisting}

\section{\textit{Objective Function}}

Fungsi objektif memberi nilai pada state berdasarkan total nilai paket yang berhasil dimuat. Untuk state $S=(P,T,\phi)$, definisikan $I^+(S)=\{i\in P\mid\phi(i)\neq\bot\}$ sebagai paket yang berada di dalam truk. Nilai state dan tujuan optimasinya adalah

\begin{align}
    f(S) & = \sum_{i\in I^+(S)} v_i,
    \label{eq:objective-value}                                  \\
    S^*  & \in \operatorname*{arg\,max}_{S\in\mathcal{F}} f(S),
    \label{eq:objective-max}
\end{align}

dengan $v_i$ adalah nilai paket $i$ dan $\mathcal{F}$ adalah himpunan state yang memenuhi seluruh constraint pada bagian sebelumnya. Dengan demikian, paket yang berada di luar truk tidak menyumbang nilai, sementara paket dengan nilai lebih tinggi meningkatkan nilai objektif jika dapat dimuat tanpa melanggar constraint. Fungsi ini tidak memberi bonus langsung untuk ruang kosong atau penalti berat; berat hanya membatasi state melalui constraint kapasitas. Implementasi menghitung jumlah nilai paket yang memiliki penempatan, seperti ditunjukkan pada Kode~\ref{lst:objective-function}.

\begin{lstlisting}[caption={Perhitungan nilai objektif sebuah state},label={lst:objective-function}]
def objective(self):
    return sum(
        package.value
        for package in self.packages
        if self.placements[package.id] is not None
    )
\end{lstlisting}

\section{Formulasi \textit{Initial State}}

Program membentuk state awal secara konstruktif dan acak, bukan dengan mengambil sampel seragam dari seluruh state layak. Mula-mula semua paket dianggap berada di luar truk, kemudian paket diproses dalam urutan acak. Proses untuk paket ke-$k$ dapat diringkas sebagai

\begin{enumerate}
    \renewcommand{\labelenumi}{(\arabic{enumi})}
    \item Atur penempatan awal setiap paket menjadi $\bot$, yang menandakan paket berada di luar truk.
    \item Acak urutan paket yang akan dicoba.
    \item Untuk setiap paket, coba hingga 50 kali secara default. Pada tiap percobaan, pilih orientasi secara acak, lalu pilih koordinat yang muat di dalam truk.
    \item Terima penempatan pertama yang menghasilkan state valid. Jika semua percobaan gagal, biarkan paket tersebut di luar truk dan lanjutkan ke paket berikutnya.
\end{enumerate}

Secara formal, jika $\sigma$ adalah urutan acak paket, penempatan dimulai dengan $\phi_0(i)=\bot$ untuk setiap $i\in P$. Pada langkah $k$, kandidat $\phi_k'$ mengganti penempatan paket $\sigma_k$; kandidat diterima hanya jika $\operatorname{validate}(P,T,\phi_k')=\emptyset$. Setelah seluruh paket diproses, pemetaan yang terbentuk menjadi state awal $S_0=(P,T,\phi)$. Koordinat horizontal dipilih acak dari rentang integer yang muat, sedangkan koordinat $z$ dipilih dari lantai truk atau ketinggian permukaan atas paket yang sudah ditempatkan. Kode~\ref{lst:initial-state} memperlihatkan inti proses tersebut.

\begin{lstlisting}[caption={Pembentukan state awal acak yang valid},label={lst:initial-state}]
def random_initial_state(packages, truck, rng=None, attempts_per_package=50):
    rng = rng or Random()
    placements = {package.id: None for package in packages}
    order = list(packages)
    rng.shuffle(order)

    for package in order:
        for _ in range(attempts_per_package):
            orientation = rng.choice(ORIENTATIONS)
            dimensions = package.oriented_dimensions(orientation)
            if any(size > limit for size, limit in zip(dimensions, truck.dimensions)):
                continue
            candidate_placements = placements.copy()
            candidate_placements[package.id] = _candidate_position(
                package, orientation, truck, placements, rng
            )
            candidate = _make_state(packages, truck, candidate_placements)
            if _valid(candidate):
                placements = candidate_placements
                break

    return _make_state(packages, truck, placements)
\end{lstlisting}

Karena paket diproses satu per satu dengan jumlah percobaan terbatas, hasil state awal bergantung pada urutan dan bilangan acak yang digunakan; paket yang gagal ditempatkan tidak menghalangi paket berikutnya untuk dicoba. Strategi ini selalu mempertahankan state valid, tetapi tidak menjamin nilai awal maksimum atau bahwa setiap paket yang sebenarnya dapat dimuat akan berhasil ditempatkan.

\section{Implementasi Hill Climbing}

Seluruh varian \textit{hill climbing} diimplementasikan pada berkas \texttt{src/\allowbreak algorithms/\allowbreak hill\_\allowbreak climbing/\allowbreak algorithm.py} di atas representasi \textit{state}, validator \textit{constraint}, dan fungsi \textit{neighbor} yang sama dengan algoritma lainnya (\texttt{State}, \texttt{validate\_state}, dan \texttt{random\_neighbor}). Dengan demikian seluruh algoritma menerima masukan dan mengembalikan keluaran yang seragam, yaitu objek \texttt{SearchResult} yang memuat \textit{state} awal, \textit{state} akhir, nilai \textit{objective function} akhir, riwayat nilai per iterasi, durasi pencarian, dan metrik khusus algoritma.

\subsection{Pembangkitan \textit{Neighbor} dan Heuristik}
Ruang \textit{neighbor} pada permasalahan ini sangat besar karena koordinat paket berupa bilangan bulat, sehingga seluruh \textit{neighbor} tidak dapat dienumerasi pada setiap iterasi. Sebagai gantinya, setiap \textit{neighbor} dibangkitkan oleh \texttt{random\_neighbor}, yang secara acak memilih salah satu dari tiga operasi (menukar dua paket, memindahkan paket ke koordinat lain, atau merotasi paket $90^{\circ}$) dan hanya mengembalikan \textit{state} yang lolos validasi \textit{constraint}.

Heuristik yang kami gunakan adalah \textit{steepest} berbasis sampel: pada setiap iterasi dibangkitkan \texttt{neighbors\_per\_iteration} (bawaan 30) \textit{neighbor} valid, kemudian \textit{neighbor} dengan nilai terbaik dianggap sebagai \textit{neighbor} terbaik. Konsekuensinya, varian \textit{steepest} dan \textit{sideways} tidak menjamin menemukan \textit{neighbor} terbaik yang sesungguhnya, tetapi peluangnya naik seiring bertambahnya ukuran sampel. Varian \textit{stochastic} memakai tepat satu \textit{neighbor} per iterasi.

\begin{itemize}
    \item \textit{Steepest}: berhenti ketika \textit{neighbor} terbaik dari sampel tidak lebih baik daripada \textit{state} saat ini.
    \item \textit{Sideways}: sama seperti \textit{steepest}, tetapi \textit{neighbor} bernilai sama diterima selama jumlah \textit{sideways move} belum mencapai \texttt{max\_sideways}.
    \item \textit{Stochastic}: berhenti setelah \texttt{max\_iterations} iterasi. Iterasi yang \textit{neighbor}-nya ditolak tetap dihitung.
    \item \textit{Random restart}: menjalankan \textit{steepest} dari \textit{state} awal yang diberikan, lalu dari \texttt{max\_restarts} \textit{state} acak baru, sehingga total terdapat \texttt{max\_restarts}\,+\,1 pendakian. Hasil terbaik dari seluruh pendakian dikembalikan.
\end{itemize}

\subsection{Metrik yang Dicatat}
Setiap \textit{run} mengembalikan \texttt{HillClimbingMetrics} yang berisi varian yang dipakai, banyak iterasi hingga berhenti, jumlah dan batas \textit{sideways move}, jumlah dan batas \textit{restart}, serta banyak iterasi pada setiap \textit{restart}. Riwayat nilai \textit{objective function} dicatat pada setiap iterasi (elemen pertama adalah nilai \textit{state} awal) dan digunakan untuk membuat plot nilai \textit{objective function} terhadap banyak iterasi. Durasi pencarian diukur dengan \texttt{perf\_counter}.

\subsection{\textit{Source Code}}
Fungsi \texttt{\_climb} menjalankan satu pendakian untuk varian \textit{steepest}, \textit{sideways}, atau \textit{stochastic}. Fungsi \texttt{hill\_climbing} memvalidasi parameter, memilih varian, menangani pengulangan pada \textit{random restart}, lalu menyusun \texttt{SearchResult}.

\begin{lstlisting}[language=Python, caption={Fungsi bantu dan \texttt{\_climb} pada \texttt{algorithm.py}}]
from math import isfinite
from random import Random
from time import perf_counter

from src.contracts import ObjectiveFunction, resolve_objective
from src.model import State
from src.neighbors import random_initial_state, random_neighbor
from src.results import HillClimbingMetrics, ObjectiveValue, SearchResult

VARIANTS = ("steepest", "sideways", "stochastic", "random_restart")


def _check_int(value, name: str, minimum: int) -> None:
    if type(value) is not int or value < minimum:
        raise ValueError(f"{name} must be an integer >= {minimum}")


def _score(objective: ObjectiveFunction[State], state: State) -> ObjectiveValue:
    score = objective(state)
    if isinstance(score, bool) or not isinstance(score, (int, float)) or not isfinite(score):
        raise ValueError("objective_fn must return finite integer or float values")
    return score


def _climb(
    start: State,
    objective: ObjectiveFunction[State],
    rng: Random,
    *,
    variant: str,
    neighbors_per_iteration: int,
    max_iterations: int,
    max_sideways: int,
) -> tuple[State, ObjectiveValue, list[ObjectiveValue], int, int]:
    """One climb. Returns (state, score, history, iterations, sideways_moves).

    history[0] is the start score; one entry is appended per iteration.
    """
    current, current_score = start, _score(objective, start)
    history = [current_score]
    iterations = sideways = 0

    while iterations < max_iterations:
        if variant == "stochastic":
            candidates = [random_neighbor(current, rng)]
        else:
            candidates = [random_neighbor(current, rng) for _ in range(neighbors_per_iteration)]
        scored = [(_score(objective, c), c) for c in candidates]
        best_score, best = max(scored, key=lambda pair: pair[0])

        if best_score > current_score:
            current, current_score = best, best_score
        elif variant == "sideways" and best_score == current_score and sideways < max_sideways:
            current = best
            sideways += 1
        elif variant == "stochastic":
            iterations += 1  # a rejected random neighbor still costs an iteration
            history.append(current_score)
            continue
        else:
            break  # local optimum (or sideways budget exhausted)
        iterations += 1
        history.append(current_score)

    return current, current_score, history, iterations, sideways
\end{lstlisting}

    *,
    seed: int,
    objective_fn: ObjectiveFunction[State] | None = None,
    variant: str = "steepest",
    neighbors_per_iteration: int = 30,
    max_iterations: int = 1000,
    max_sideways: int = 100,
    max_restarts: int = 10,
    objective_name: str | None = None,
    run_index: int = 1,
) -> SearchResult[State]:
    """Run one hill-climbing variant and return a shared-contract SearchResult."""
    if variant not in VARIANTS:
        raise ValueError(f"variant must be one of {VARIANTS}")
    if type(seed) is not int:
        raise ValueError("seed must be an integer")
    _check_int(neighbors_per_iteration, "neighbors_per_iteration", 1)
    _check_int(max_iterations, "max_iterations", 0)
    _check_int(max_sideways, "max_sideways", 0)
    _check_int(max_restarts, "max_restarts", 0)
    _check_int(run_index, "run_index", 1)

    started_at = perf_counter()
    rng = Random(seed)
    objective = resolve_objective(initial_state, objective_fn)
    climb_kwargs = dict(
        variant="steepest" if variant == "random_restart" else variant,
        neighbors_per_iteration=neighbors_per_iteration,
        max_iterations=max_iterations,
        max_sideways=max_sideways,
    )

    if variant == "random_restart":
        # Restart 0 uses the supplied initial state; each later one a fresh random state.
        best_state, best_score = initial_state, None
        history: list[ObjectiveValue] = []
        per_restart: list[int] = []
        for restart in range(max_restarts + 1):
            start = (
                initial_state
                if restart == 0
                else random_initial_state(initial_state.packages, initial_state.truck, rng)
            )
            state, score, hist, iters, _ = _climb(start, objective, rng, **climb_kwargs)
            history.extend(hist)
            per_restart.append(iters)
            if best_score is None or score > best_score:
                best_state, best_score = state, score
        final_state, final_score = best_state, best_score
        iterations, sideways = sum(per_restart), 0
        restarts = max_restarts
    else:
        final_state, final_score, history, iterations, sideways = _climb(
            initial_state, objective, rng, **climb_kwargs
        )
        per_restart, restarts = [], 0

    parameters: dict[str, int | float | str | bool] = {
        "variant": variant,
        "max_iterations": max_iterations,
    }
    if variant != "stochastic":
        parameters["neighbors_per_iteration"] = neighbors_per_iteration
    if variant == "sideways":
        parameters["max_sideways"] = max_sideways
    if variant == "random_restart":
        parameters["max_restarts"] = max_restarts

    return SearchResult(
        algorithm=f"hill_climbing_{variant}",
        objective_name=objective_name or ("total_value" if objective_fn is None else "custom"),
        initial_state=initial_state,
        final_state=final_state,
        objective_value=final_score,
        objective_history=tuple(history),
        duration_seconds=perf_counter() - started_at,
        metrics=HillClimbingMetrics(
            variant=variant,
            iterations=iterations,
            sideways_moves=sideways,
            maximum_sideways_moves=max_sideways if variant == "sideways" else None,
            restarts=restarts,
            maximum_restarts=max_restarts if variant == "random_restart" else None,
            iterations_per_restart=tuple(per_restart),
        ),
        seed=seed,
        run_index=run_index,
        parameters=parameters,
    )
\end{lstlisting}

\section{Implementasi Simulated Annealing}

Implementasi \textit{Simulated Annealing} (SA) berada pada berkas \texttt{src/\allowbreak algorithms/\allowbreak simulated\_\allowbreak annealing/\allowbreak algorithm.py}. Algoritma ini memakai representasi \texttt{State}, validator \textit{constraint}, dan fungsi \texttt{random\_neighbor} yang sama dengan \textit{hill climbing} dan \textit{genetic algorithm}, serta mengembalikan objek \texttt{SearchResult} yang seragam. Seluruh fungsi pada algoritma ini terdapat dalam satu fungsi \texttt{simulated\_annealing}; uraian berikut mengikuti urutan eksekusinya.

\subsection{Parameter dan Validasi Masukan}

Pemanggil menyediakan \textit{state} awal, \textit{seed}, jumlah iterasi maksimum, temperatur awal, dan laju pendinginan. Fungsi objektif dapat berupa \texttt{State.objective} atau fungsi lain yang diberikan pemanggil. Fungsi memeriksa bahwa \textit{seed} berupa bilangan bulat, \texttt{max\_iterations} tidak negatif, \texttt{initial\_temperature} bernilai hingga dan positif, serta \texttt{cooling\_rate} berada pada rentang $(0,1]$. Pelanggaran memunculkan \texttt{ValueError} sebelum pencarian dimulai.

\subsection{Skema Pendinginan dan Probabilitas Penerimaan}

Temperatur diturunkan secara geometris. Pada iterasi ke-$t$, temperatur adalah
\begin{equation}
    T_t = T_0\,\alpha^{t},
    \label{eq:sa-cooling}
\end{equation}
dengan $T_0$ sebagai temperatur awal dan $\alpha$ sebagai \texttt{cooling\_rate}. Karena persoalan ini adalah maksimisasi, selisih nilai kandidat terhadap \textit{state} saat ini ditulis $\Delta E=f(S')-f(S)$. Kandidat yang tidak lebih buruk ($\Delta E\ge 0$) selalu diterima, sedangkan kandidat yang lebih buruk diterima dengan peluang
\begin{equation}
    P(\text{terima})=
    \begin{cases}
        1                & \Delta E \ge 0, \\
        e^{\Delta E/T_t} & \Delta E < 0.
    \end{cases}
    \label{eq:sa-acceptance}
\end{equation}
Semakin rendah temperatur atau semakin besar penurunan nilai, semakin kecil peluang menerima langkah yang memburuk. Kode~\ref{lst:sa-acceptance} menunjukkan fungsi bantu yang menghitung peluang ini.

\begin{lstlisting}[language=Python, caption={Peluang penerimaan kandidat},label={lst:sa-acceptance}]
def _acceptance_probability(delta, temperature):
    if delta >= 0:
        return 1.0
    if temperature <= 0:
        return 0.0
    return exp(delta / temperature)
\end{lstlisting}

\subsection{Loop Pencarian}

Pencarian dimulai dari \textit{state} awal yang diberikan. Pada setiap iterasi, satu \textit{neighbor} valid dibangkitkan oleh \texttt{random\_neighbor}, nilainya dievaluasi, lalu peluang pada Persamaan~\ref{eq:sa-acceptance} dicatat. Kandidat diterima jika $\Delta E\ge 0$ atau jika bilangan acak seragam pada $[0,1)$ lebih kecil daripada peluang tersebut. Setelah itu, temperatur dikalikan dengan \texttt{cooling\_rate}. Selain \textit{state} saat ini, algoritma menyimpan \textit{state} terbaik yang pernah dijumpai sehingga langkah yang memburuk tidak menghilangkan solusi terbaik.

\begin{lstlisting}[language=Python, caption={Loop utama \textit{simulated annealing}},label={lst:sa-loop}]
rng = Random(seed)
objective = resolve_objective(initial_state, objective_fn)
current = best = initial_state
current_score = best_score = _validate_objective(objective(current))
temperature = float(initial_temperature)

for _ in range(max_iterations):
    candidate = random_neighbor(current, rng)
    candidate_score = _validate_objective(objective(candidate))
    delta = candidate_score - current_score
    acceptance_probability = _acceptance_probability(delta, temperature)
    acceptance_history.append(acceptance_probability)
    temperature_history.append(temperature)

    if delta >= 0 or rng.random() < acceptance_probability:
        current, current_score = candidate, candidate_score

    if current_score > best_score:
        best, best_score = current, current_score
        stalled_iterations = 0
        plateau_counted = False
    else:
        stalled_iterations += 1
        if stalled_iterations >= stuck_patience and not plateau_counted:
            stuck_count += 1
            plateau_counted = True
    objective_history.append(best_score)
    current_history.append(current_score)
    temperature *= cooling_rate
\end{lstlisting}

Pengujian \texttt{delta >= 0} sebelum pemanggilan \texttt{rng.random()} berarti kandidat yang tidak lebih buruk tidak mengonsumsi bilangan acak, sehingga urutan keputusan acak tetap deterministik untuk \textit{seed} yang sama. Karena \texttt{random\_neighbor} mengembalikan \textit{state} asal ketika tidak menemukan kandidat valid, iterasi tersebut menghasilkan $\Delta E=0$ dan \textit{state} tidak berubah.

\subsection{Deteksi \textit{Stuck} pada Optimum Lokal}

Spesifikasi meminta frekuensi algoritma terjebak pada optimum lokal. Implementasi mengukurnya melalui \texttt{stuck\_count}, yaitu banyaknya plateau terpisah tempat nilai terbaik tidak membaik selama \texttt{stuck\_patience} iterasi berturut-turut. Penghitung \texttt{stalled\_iterations} direset setiap kali nilai terbaik meningkat, dan penanda \texttt{plateau\_counted} mencegah satu plateau panjang dihitung berulang kali. Dengan demikian, satu plateau yang berlangsung ratusan iterasi hanya menambah \texttt{stuck\_count} sebanyak satu, dan plateau baru hanya dihitung setelah ada perbaikan terbaik yang baru.

\subsection{Metrik dan Hasil}

Setelah iterasi selesai, algoritma mengemas \textit{state} terbaik dan metrik ke dalam \texttt{SearchResult}. \texttt{SimulatedAnnealingMetrics} memuat jumlah iterasi, \texttt{stuck\_count} beserta ambangnya, riwayat nilai \textit{state} saat ini, riwayat temperatur, dan riwayat $e^{\Delta E/T}$ (peluang penerimaan) pada setiap iterasi. Riwayat objektif pada \texttt{objective\_history} menyimpan nilai terbaik sejauh ini, dengan elemen pertama berupa nilai \textit{state} awal, sedangkan riwayat nilai \textit{state} saat ini disimpan terpisah agar dapat memperlihatkan langkah yang memburuk. Karena \texttt{final\_state} adalah \textit{state} terbaik yang pernah dijumpai, nilainya tidak pernah lebih rendah daripada nilai \textit{state} awal.

\begin{lstlisting}[language=Python, caption={Mengemas solusi dan metrik hasil pencarian SA},label={lst:sa-result}]
return SearchResult(
    algorithm="simulated_annealing",
    objective_name=objective_name or ("total_value" if objective_fn is None else "custom"),
    initial_state=initial_state,
    final_state=best,
    objective_value=best_score,
    objective_history=tuple(objective_history),
    duration_seconds=perf_counter() - started_at,
    metrics=SimulatedAnnealingMetrics(
        iterations=max_iterations,
        exp_delta_e_over_temperature=tuple(acceptance_history),
        stuck_count=stuck_count,
        stuck_patience=stuck_patience,
        current_objective_history=tuple(current_history),
        temperature_history=tuple(temperature_history),
    ),
    seed=seed,
    run_index=run_index,
    parameters={
        "max_iterations": max_iterations,
        "initial_temperature": initial_temperature,
        "cooling_rate": cooling_rate,
        "stuck_patience": stuck_patience,
    },
)
\end{lstlisting}

\section{Implementasi Genetic Algorithm}

Implementasi Genetic Algorithm pada proyek ini menyimpan tiap individu sebagai objek \texttt{State}. Karena itu, satu gen berkorespondensi dengan penempatan satu paket, termasuk status paket di luar truk. Alur algoritma dipisah ke beberapa modul agar pembentukan populasi, seleksi, crossover, mutasi, dan loop generasi dapat dijelaskan serta diuji secara terpisah. Uraian berikut mengikuti urutan eksekusi \texttt{genetic\_algorithm}.

\subsection{Konfigurasi dan Generator Acak}

Pemanggil menyediakan state awal, seed, ukuran populasi, dan jumlah generasi. Laju mutasi secara default adalah $0{,}05$, seleksi default menggunakan \textit{roulette wheel}, dan crossover diaktifkan. Seed dipakai untuk menginisialisasi satu generator acak yang digunakan bersama oleh seluruh tahap, sehingga run dengan masukan dan seed yang sama dapat direproduksi. Fungsi objektif dapat menggunakan metode \texttt{State.objective} atau fungsi objektif lain yang diberikan pemanggil.

\begin{lstlisting}[caption={Menyiapkan pencarian GA},label={lst:ga-setup}]
rng = Random(seed)
objective = resolve_objective(initial_state, objective_fn)
population = initialize_population(initial_state, population_size, rng)
\end{lstlisting}

\subsection{Inisialisasi Populasi}

Populasi pertama harus berisi state valid dan selalu menyertakan \texttt{initial\_state} sebagai individu pertama. Anggota lainnya dibentuk menggunakan generator state awal acak yang dijelaskan sebelumnya. Dengan cara ini, algoritma memulai pencarian dari solusi yang diberikan sekaligus mempertimbangkan konfigurasi alternatif. Fungsi \texttt{initialize\_population} memastikan ukuran populasi positif dan menolak state awal yang melanggar constraint.

\begin{lstlisting}[caption={Membangun populasi awal},label={lst:ga-initialize-population}]
def initialize_population(initial_state, population_size, rng):
    if type(population_size) is not int or population_size < 1:
        raise ValueError("population_size must be a positive integer")
    violations = validate_state(initial_state)
    if violations:
        raise ValueError(f"initial_state is invalid: {'; '.join(violations)}")

    return (
        initial_state,
        *(
            random_initial_state(initial_state.packages, initial_state.truck, rng)
            for _ in range(population_size - 1)
        ),
    )
\end{lstlisting}

\subsection{Evaluasi \textit{Fitness} dan Penyimpanan Individu Terbaik}

Pada awal setiap generasi, nilai objektif setiap individu dihitung sebagai \textit{fitness}. Implementasi juga memastikan setiap nilai berupa bilangan hingga. Individu dengan nilai tertinggi pada generasi tersebut dicatat, begitu pula rata-rata fitness populasi. Di luar populasi yang sedang berjalan, \texttt{best\_state} dan \texttt{best\_score} menyimpan solusi terbaik yang pernah ditemukan, sehingga solusi tersebut tetap dapat dikembalikan walaupun tidak terpilih menjadi induk atau tidak muncul pada generasi berikutnya.

\begin{lstlisting}[caption={Evaluasi populasi dan pembaruan solusi terbaik},label={lst:ga-evaluate}]
fitnesses = _evaluate_population(population, objective)
generation_best_index = max(
    range(len(population)), key=fitnesses.__getitem__
)
generation_best_score = fitnesses[generation_best_index]
best_history.append(generation_best_score)
average_history.append(sum(fitnesses) / len(fitnesses))

if best_score is None or generation_best_score > best_score:
    best_state = population[generation_best_index]
    best_score = generation_best_score
\end{lstlisting}

\subsection{Seleksi Induk dengan \textit{Roulette Wheel}}

Untuk menghasilkan anak, program memilih dua induk dari populasi saat ini. Pada konfigurasi standar, seleksi menggunakan \textit{roulette wheel}: individu dengan fitness lebih tinggi mendapat peluang lebih besar untuk dipilih, tetapi individu lain tetap berpeluang terpilih. Karena fungsi objektif pemuatan paket bernilai nonnegatif, nilainya langsung digunakan sebagai bobot. Implementasi juga menangani fitness negatif dengan menggeser bobot, dan memilih secara seragam apabila semua bobot bernilai nol. Mode seleksi seragam tersedia sebagai opsi eksperimen.

\begin{lstlisting}[caption={Pemilihan induk secara roulette},label={lst:ga-selection}]
minimum = min(fitnesses)
weights = [fitness - minimum if minimum < 0 else fitness
           for fitness in fitnesses]
if sum(weights) == 0:
    return rng.choice(population)
return rng.choices(population, weights=weights, k=1)[0]
\end{lstlisting}

\subsection{Crossover Satu Titik dan Perbaikan Kelayakan}

Setelah dua induk dipilih, \textit{single-point crossover} mengambil gen sebelum titik potong dari induk pertama dan gen setelahnya dari induk kedua. Urutan gen mengikuti urutan paket dalam state. Anak mula-mula dibuat dengan semua paket di luar truk, lalu paket-paket yang diwarisi dalam keadaan termuat dicoba satu per satu dari ketinggian terendah. Jika penempatan warisan membuat anak melanggar constraint, program mencoba mencari penempatan valid baru untuk paket itu; jika pencarian perbaikan gagal, paket tetap di luar truk. Dengan demikian, anak yang dihasilkan tetap layak.

\begin{lstlisting}[caption={Mengambil gen dari dua induk pada satu titik potong},label={lst:ga-crossover-gene}]
cut = rng.randrange(1, len(packages)) if len(packages) > 1 else 1
inherited = {
    package.id: (
        parent_a.placements[package.id]
        if index < cut
        else parent_b.placements[package.id]
    )
    for index, package in enumerate(packages)
}
\end{lstlisting}

Cuplikan tersebut menentukan pewarisan gen. Tahap berikutnya membangun state anak dan memvalidasi setiap penempatan yang diwarisi. Kode di bawah menunjukkan penanganan gen yang tidak dapat langsung dipasang secara valid.

\begin{lstlisting}[caption={Mempertahankan validitas anak hasil crossover},label={lst:ga-crossover-repair}]
candidate = State(packages, parent_a.truck, placements)
if not validate_state(candidate):
    child = candidate
else:
    repaired = random_valid_placement(child, package, rng)
    if repaired is not None:
        placements = dict(child.placements)
        placements[package.id] = repaired
        child = State(packages, parent_a.truck, placements)
\end{lstlisting}

\subsection{Mutasi Anak}

Setiap anak kemudian mengalami mutasi dengan peluang \texttt{mutation\_rate}, yang secara default bernilai $0{,}05$. Artinya, peluang tersebut diterapkan pada setiap anak yang dibentuk, bukan secara terpisah pada setiap paket. Jika mutasi terpilih, satu paket dipilih secara acak. Paket yang belum dimuat dicoba untuk dimasukkan; paket yang sudah dimuat dapat dipindahkan, dirotasi, atau dikeluarkan. Kandidat mutasi hanya diterima jika berbeda dari penempatan lama dan seluruh state tetap valid. Fungsi mencoba paling banyak 50 kandidat; jika tidak menemukan mutasi valid, individu tidak berubah.

\begin{lstlisting}[caption={Peluang mutasi pada setiap anak},label={lst:ga-mutation-rate}]
if rng.random() < mutation_rate:
    child = mutate_individual(child, rng)
next_population.append(child)
\end{lstlisting}

\begin{lstlisting}[caption={Memilih satu paket dan jenis mutasinya},label={lst:ga-mutation-operator}]
package = rng.choice(individual.packages)
old = individual.placements[package.id]
operations = ("insert",) if old is None else ("move", "rotate", "remove")
for _ in range(attempts):
    operation = rng.choice(operations)
    if operation == "remove":
        placement = None
    elif operation == "rotate":
        assert old is not None
        placement = random_valid_placement(
            individual, package, rng,
            orientation=rng.choice(tuple(o for o in ORIENTATIONS if o != old.orientation)),
            coordinate=old.coordinate, attempts=1,
        )
    else:
        placement = random_valid_placement(
            individual, package, rng,
            orientation=old.orientation if old is not None else None,
            attempts=1,
        )
    if placement == old:
        continue
    placements = dict(individual.placements)
    placements[package.id] = placement
    candidate = State(individual.packages, individual.truck, placements)
    if not validate_state(candidate):
        return candidate
return individual
\end{lstlisting}

\subsection{Pembentukan Generasi Berikutnya dan Terminasi}

Anak-anak dibuat berulang kali sampai jumlahnya sama dengan \texttt{population\_size}. Populasi baru kemudian menggantikan populasi lama secara generasional; individu terbaik tidak otomatis disalin ke generasi berikutnya, tetapi solusi terbaik global tetap tersimpan dalam \texttt{best\_state}. Loop mengevaluasi generasi awal bernomor nol hingga generasi ke-$G$, sehingga menghasilkan $G+1$ catatan fitness. Setelah generasi terakhir dievaluasi, pencarian berhenti dan hasil akhirnya memuat state dengan fitness terbaik yang pernah dijumpai, riwayat fitness terbaik dan rata-rata per generasi, durasi, seed, serta parameter pencarian.

\begin{lstlisting}[caption={Loop generasi dan pembentukan populasi baru},label={lst:ga-generation-loop}]
best_history = []
average_history = []
best_state = initial_state
best_score = None

for generation in range(generations + 1):
    fitnesses = _evaluate_population(population, objective)
    best_index = max(range(len(population)), key=fitnesses.__getitem__)
    generation_best = fitnesses[best_index]
    best_history.append(generation_best)
    average_history.append(sum(fitnesses) / len(fitnesses))
    if best_score is None or generation_best > best_score:
        best_state = population[best_index]
        best_score = generation_best
    if generation == generations:
        break

    next_population = []
    while len(next_population) < population_size:
        if selection_mode == "uniform":
            parent_a = rng.choice(population)
            parent_b = rng.choice(population)
        else:
            parent_a = roulette_wheel_select(population, fitnesses, rng)
            parent_b = roulette_wheel_select(population, fitnesses, rng)
        child = (single_point_crossover(parent_a, parent_b, rng)
                 if crossover_enabled else parent_a)
        if rng.random() < mutation_rate:
            child = mutate_individual(child, rng)
        next_population.append(child)
    population = tuple(next_population)
\end{lstlisting}

Setelah generasi terakhir dievaluasi, algoritma mengemas solusi terbaik dan metrik pencarian ke dalam objek \texttt{SearchResult}. Seed, indeks run, dan parameter pencarian turut dicatat agar hasil eksperimen dapat ditelusuri.

\section{Implementasi Spesifikasi Bonus}

\subsection{\textit{Extra} Objective Function}

Dua \textit{objective function} tambahan diimplementasikan pada \texttt{src/\allowbreak objectives.py}. Keduanya hanya memakai variabel masalah yang sudah ada (nilai, ETA, penempatan, dan ukuran truk), tidak menambah data baru, dan didaftarkan bersama \texttt{total\_value} pada kamus \texttt{OBJECTIVES} sehingga dapat dipilih dengan nama dari runner eksperimen.

\begin{itemize}
    \item \texttt{eta\_weighted\_value}\,$=\sum_{i\in\text{truk}} \dfrac{v_i}{e_i+1}$, dengan $v_i$ nilai dan $e_i$ ETA paket $i$. Paket yang mendesak ($e_i$ kecil) memberi kontribusi lebih besar: paket dengan ETA 0 bernilai penuh, sedangkan paket dengan ETA 3 hanya seperempatnya.
    \item \texttt{compact\_value}\,$=\text{total\_value} + 0{,}99\cdot\left(1-\dfrac{\sum_i (z_i+h_i)\,V_i}{H\sum_i V_i}\right)$, dengan $z_i$ koordinat vertikal, $h_i$ tinggi terorientasi, $V_i$ volume paket, dan $H$ tinggi truk. Suku kedua bernilai di bawah satu satuan nilai, sehingga \textit{state} dengan nilai total lebih besar selalu menang dan suku ini hanya berperan sebagai pemecah seri yang mengarahkan tumpukan ke bawah. Dengan demikian dataran pada \texttt{total\_value} (gerakan atau rotasi yang mempertahankan himpunan paket) berubah menjadi gradien.
\end{itemize}

\begin{lstlisting}[language=Python, caption={Fungsi \textit{objective} tambahan pada \texttt{objectives.py}}]
_COMPACTNESS_SCALE = 0.99


def eta_weighted_value(state: State) -> float:
    return sum(
        package.value / (package.eta + 1)
        for package in state.packages
        if state.placements[package.id] is not None
    )


def compact_value(state: State) -> float:
    return state.objective() + _COMPACTNESS_SCALE * compactness(state)


OBJECTIVES = {
    "total_value": total_value,
    "eta_weighted_value": eta_weighted_value,
    "compact_value": compact_value,
}
\end{lstlisting}

Fungsi \texttt{compactness} menghitung satu dikurangi rata-rata tinggi puncak paket yang dibobot volume dan dinormalisasi terhadap tinggi truk, sehingga bernilai dalam $[0,1]$ dan bernilai 0 untuk truk kosong. Setiap algoritma menerima \textit{objective} melalui parameter \texttt{objective\_fn} pada kontrak yang sama, dan \texttt{src/\allowbreak experiments/\allowbreak objective\_comparison.py} menyediakan fungsi bersama untuk memilih \textit{objective} berdasarkan nama serta menilai ulang setiap \textit{state} akhir dengan \texttt{total\_value} agar perbandingan antar-\textit{objective} adil.

\subsection{All-variant Hill Climbing Algorithm}

Keempat varian \textit{hill climbing} (\textit{steepest}, \textit{sideways}, \textit{stochastic}, dan \textit{random restart}) sudah dijelaskan beserta kode sumbernya pada bagian Implementasi \textit{Hill Climbing}. Seluruhnya berbagi satu fungsi \texttt{hill\_climbing} dengan parameter \texttt{variant} dan satu fungsi pendakian \texttt{\_climb}, sehingga perbedaan hasil antar-varian hanya berasal dari aturan penerimaan \textit{neighbor} dan kondisi berhenti. Varian tersebut dapat dijalankan bersamaan dengan salah satu dari tiga \textit{objective function} melalui parameter \texttt{objective\_fn}.

\subsection{Multi-Truck}

\subsubsection{Representasi \textit{State} Armada}

Representasi satu truk tidak cukup untuk memodelkan penugasan paket ke beberapa truk. Implementasi menggunakan \texttt{FleetState} untuk menyimpan kumpulan paket, daftar truk, dan satu peta penempatan untuk setiap truk. Untuk $n$ paket dan $m$ truk, misalkan $I=\{1,\ldots,n\}$ adalah indeks paket dan $J=\{1,\ldots,m\}$ adalah indeks truk. State armada ditulis sebagai

\begin{equation}
    S_F = (P, (T_j)_{j\in J}, (\phi_j)_{j\in J}),
    \qquad
    \phi_j : I \longrightarrow \{\bot\}\cup\mathcal{P}_j,
    \label{eq:fleet-state}
\end{equation}

Notasi $P$ menyatakan kumpulan paket, $T_j$ menyatakan truk ke-$j$, dan $\mathcal{P}_j$ menyatakan himpunan penempatan yang mungkin pada truk tersebut. Nilai $\phi_j(i)=\bot$ berarti paket $i$ tidak ditempatkan pada truk $j$. Jika paket ditempatkan, nilainya memuat koordinat, dimensi setelah rotasi, dan orientasi paket. Secara internal, $\phi_j$ direpresentasikan oleh kamus dari ID paket ke objek \texttt{Placement | None}. Tuple kamus tersebut disimpan pada \texttt{FleetState.placements}, sejajar dengan tuple \texttt{trucks}.

Satu \textit{state} armada berisi daftar paket, daftar truk, dan tabel penempatan untuk setiap truk. Tiap sel pada tabel menunjukkan apakah sebuah paket berada di truk tersebut. Jika paket dimuat, sel itu juga menyimpan posisi dan orientasinya.

Setiap paket boleh tidak dimuat atau ditempatkan pada tepat satu truk. Dengan fungsi indikator $\mathbf{1}[\cdot]$, batasan keunikan assignment dirumuskan sebagai

\begin{equation}
    \sum_{j\in J}\mathbf{1}[\phi_j(i)\neq\bot]\leq 1,
    \qquad \forall i\in I.
    \label{eq:fleet-unique-assignment}
\end{equation}

Untuk setiap paket, jumlah truk yang memuatnya harus nol atau satu. Nilai nol berarti paket belum termuat, sedangkan nilai satu berarti paket ditugaskan ke sebuah truk. Nilai lebih dari satu menunjukkan bahwa paket yang sama tercatat ganda.

Paket yang tidak memperoleh penempatan valid tetap tercatat pada kumpulan $P$. Seluruh entri penempatannya bernilai $\bot$. Cuplikan~\ref{lst:fleet-state} menunjukkan struktur data tersebut.

\begin{lstlisting}[language=Python, caption={Representasi state armada pada \texttt{model.py}},label={lst:fleet-state}]
@dataclass(frozen=True, slots=True)
class FleetState:
    packages: tuple[Package, ...]
    trucks: tuple[Truck, ...]
    placements: tuple[Mapping[str, Placement | None], ...]

    def __post_init__(self):
        if not self.trucks or len(self.placements) != len(self.trucks):
            raise ValueError("fleet needs one placement map per truck")
        for truck, placements in zip(self.trucks, self.placements):
            State(self.packages, truck, placements)
\end{lstlisting}

Konstruktor memeriksa bahwa armada tidak kosong, banyak peta penempatan sama dengan banyak truk, dan setiap peta memiliki struktur yang sesuai dengan paket. Pemeriksaan kelayakan geometris dilakukan terpisah oleh validator agar aturan state satu truk tetap dapat digunakan kembali.

\subsubsection{Kelayakan Armada dan Fungsi Objektif}

Sebuah state armada layak apabila setiap truk memenuhi constraint satu truk dan tidak ada paket yang muncul pada lebih dari satu peta penempatan. Jika $\mathcal{F}_j$ adalah himpunan state yang layak untuk truk $j$, himpunan state armada layak adalah

\begin{equation}
    \mathcal{F}_F = \left\{S_F\;\middle|\;
    (P,T_j,\phi_j)\in\mathcal{F}_j\ \forall j\in J,
    \quad \sum_{j\in J}\mathbf{1}[\phi_j(i)\neq\bot]\leq 1\ \forall i\in I
    \right\}.
    \label{eq:fleet-feasible-set}
\end{equation}

Sebuah armada layak hanya jika dua syarat terpenuhi. Setiap truk harus memenuhi aturan pemuatan satu truk, dan setiap paket hanya boleh tercatat pada satu truk. Karena itu, paket yang muat secara geometris tetap membuat armada tidak layak jika tercatat ganda.

Batas dimensi, tabrakan, kapasitas berat, dan dukungan paket diperiksa pada masing-masing truk. Validator armada juga memeriksa keunikan penugasan dengan menggunakan kembali \texttt{validate\_state} dan menandai ID paket yang sudah ditempatkan.

\begin{lstlisting}[language=Python, caption={Validasi lokal dan keunikan paket pada armada},label={lst:fleet-validation}]
for truck_index, (truck, placements) in enumerate(
    zip(state.trucks, state.placements)
):
    errors.extend(
        validate_state(State(state.packages, truck, placements))
    )
    for package_id, placement in placements.items():
        if placement is None:
            continue
        if package_id in loaded_by:
            errors.append("package assigned to more than one truck")
        else:
            loaded_by[package_id] = truck_index
\end{lstlisting}

Fungsi objektif memaksimalkan total nilai paket yang berhasil dimuat di seluruh armada. Persamaan~\ref{eq:fleet-unique-assignment} memastikan setiap paket hanya dihitung satu kali.

\begin{equation}
    f_F(S_F) = \sum_{i\in I} v_i\,
    \mathbf{1}\!\left[\exists j\in J:\phi_j(i)\neq\bot\right],
    \qquad
    S_F^*\in\operatorname*{arg\,max}_{S_F\in\mathcal{F}_F} f_F(S_F).
    \label{eq:fleet-objective}
\end{equation}

$v_i$ menyatakan nilai paket ke-$i$. Indikator bernilai satu jika paket itu dimuat pada salah satu truk dan nol jika tidak. Fungsi objektif menjumlahkan nilai paket yang berhasil dimuat. Optimasi kemudian mencari state armada layak dengan jumlah nilai terbesar. Setiap paket termuat dihitung satu kali, dan $S_F^*$ menyatakan salah satu state dengan nilai tertinggi.

Implementasi \texttt{FleetState.objective()} menghitung nilai tersebut. Objective ETA dan kekompakan juga menerima \texttt{FleetState}. Objective ETA menghitung kontribusi setiap paket yang ditempatkan pada armada, sedangkan objective kekompakan mengagregasi penempatan seluruh truk.

\subsubsection{Pembentukan \textit{Initial State}}

State awal dibentuk dengan menempatkan paket satu per satu. Semua paket mula-mula belum dimuat. Paket diproses sesuai urutan masukan, sementara urutan truk untuk setiap paket diacak. Pada tiap truk, algoritma mencoba orientasi, koordinat, dan ketinggian dalam jumlah terbatas. Penempatan diterima jika state truk valid. Setelah berhasil ditempatkan, paket tidak dicoba pada truk lain. Jika seluruh percobaan gagal, paket dibiarkan di luar armada.

Untuk paket $i$ yang sedang diproses, implementasi mengacak urutan truk $J$ dan memilih truk pertama yang menyediakan kandidat $p\in\mathcal{P}_j$ sehingga penggantian $\phi_j(i)\leftarrow p$ tetap memenuhi kelayakan lokal. Pencarian dibatasi hingga 50 percobaan per truk. Jika semua percobaan gagal, paket dibiarkan di luar armada. Kegagalan ini tidak membuktikan bahwa paket mustahil dimuat. Cuplikan~\ref{lst:fleet-initialization} menunjukkan prosesnya.

\begin{lstlisting}[language=Python, caption={Inisialisasi state armada secara acak},label={lst:fleet-initialization}]
placements = tuple(
    {package.id: None for package in packages} for _ in trucks
)
fleet = FleetState(packages, trucks, placements)
for package in packages:
    truck_order = list(range(len(trucks)))
    rng.shuffle(truck_order)
    for truck_index in truck_order:
        placement = random_valid_placement(
            _truck_state(fleet, truck_index), package, rng
        )
        if placement is None:
            continue
        changed = list(fleet.placements)
        changed[truck_index] = dict(changed[truck_index])
        changed[truck_index][package.id] = placement
        fleet = FleetState(packages, trucks, tuple(changed))
        break
\end{lstlisting}

Strategi ini menggunakan generator acak ber-seed sehingga dapat direproduksi, dan menjaga agar setiap paket yang berhasil ditempatkan hanya masuk ke satu truk. Namun, strategi ini bukan pencarian menyeluruh dan tidak menjamin state awal memuat sebanyak mungkin paket.

\subsubsection{Fungsi \textit{Neighbor} untuk HC dan SA}

Pada HC dan SA, satu langkah pencarian armada mengubah assignment paling banyak satu paket. Untuk $S_F$, himpunan kandidat konseptual dapat ditulis sebagai

\begin{equation}
    N_F(S_F)=\left\{S'_F\in\mathcal{F}_F\;\middle|\;
    \left|\left\{i\in I:\gamma_i(S_F)\neq\gamma_i(S'_F)\right\}\right|\leq 1
    \right\},
    \label{eq:fleet-neighbor}
\end{equation}

Di sini, $\gamma_i(S_F)$ menunjukkan assignment paket $i$. Nilainya $\bot$ jika paket tidak dimuat, atau pasangan truk dan penempatannya jika paket dimuat. Implementasi tidak mengenumerasi semua anggota $N_F(S_F)$. Algoritma memilih satu paket secara acak, menentukan operasi yang sesuai, lalu mengambil sampel kandidat valid. Jika tidak menemukan kandidat dalam batas percobaan, operator mengembalikan state asal.

State kandidat menjadi tetangga jika tetap layak dan paling banyak satu paket berubah status atau penempatannya. Satu langkah dapat memindahkan paket ke truk lain atau ke koordinat baru, mengubah orientasinya, memasukkannya, atau mengeluarkannya. Perubahan dua paket sekaligus bukan bagian dari neighborhood satu langkah ini.

Operasi bergantung pada status paket yang dipilih. Paket yang belum dimuat hanya dapat dimasukkan ke salah satu truk. Paket yang sudah dimuat dapat dipindahkan di truk yang sama, diputar pada koordinatnya, dipindahkan ke truk lain, atau dikeluarkan dari armada. Operasi move, rotate, dan reassign hanya diterima jika penempatan pada truk tujuan valid. Validator armada juga memeriksa keunikan assignment. Operator mencoba paling banyak 50 kandidat dan mengembalikan state asal jika semua percobaan gagal.

\begin{lstlisting}[language=Python, caption={Pemilihan operasi mutasi/neighbor armada},label={lst:fleet-neighbor-operator}]
operations = ("insert",) if old is None else (
    "move", "rotate", "reassign", "remove"
)
operation = rng.choice(operations)
if operation == "remove":
    return base

truck_order = list(range(len(base.trucks)))
if operation == "move" and old_truck is not None:
    truck_order = [old_truck]
elif operation == "reassign" and old_truck is not None:
    truck_order = [i for i in truck_order if i != old_truck]
rng.shuffle(truck_order)
\end{lstlisting}

Cuplikan tersebut diambil dari awal proses mutasi. Untuk operasi selain \texttt{remove}, implementasi mencoba penempatan pada truk dalam \texttt{truck\_order}, membangun \texttt{FleetState} kandidat, lalu mengembalikannya hanya apabila berbeda dari state asal dan \texttt{validate\_fleet\_state} tidak menemukan pelanggaran.

Fungsi \texttt{\_fleet\_neighbor} pada \texttt{search\_problems.py} memakai operator ini untuk membentuk neighbor satu langkah. Loop HC dan SA tetap menggunakan implementasi generik yang sama. Adapter armada menentukan cara membentuk kandidat. HC menerima kandidat sesuai variannya, sedangkan SA juga dapat menerima kandidat yang lebih buruk dengan probabilitas yang bergantung pada temperatur.

\subsubsection{Operator \textit{Genetic Algorithm} Armada}

Pada GA, satu gen merepresentasikan assignment sebuah paket, termasuk truk dan penempatannya. Crossover satu titik mengambil gen dari induk pertama sebelum titik potong dan dari induk kedua setelahnya. Anak dibangun dari armada kosong. Gen yang diwarisi diproses menurut truk dan ketinggian penempatan. Operator terlebih dahulu mencoba mempertahankan truk, koordinat, dan orientasi asal. Jika penempatan itu berbenturan dengan gen yang sudah dipasang, operator mencari posisi lain pada truk asal, lalu mencoba truk lain. Paket yang tetap tidak dapat ditempatkan dibiarkan di luar armada.

Mutasi memilih satu paket. Untuk paket yang belum dimuat, mutasi mencoba insert. Untuk paket yang sudah dimuat, mutasi dapat memilih move, rotate, reassign, atau remove. Perubahan assignment dibangun melalui state sementara dengan paket tersebut dikeluarkan terlebih dahulu, lalu kandidat penempatan diperiksa terhadap constraint truk tujuan. Desain ini membuat mutasi satu-paket tidak perlu memodifikasi gen lain secara langsung, sekaligus menjaga keunikan assignment.

\begin{lstlisting}[language=Python, caption={Pewarisan assignment paket pada crossover fleet},label={lst:fleet-crossover}]
cut = rng.randrange(1, len(packages)) if len(packages) > 1 else 1
for package_index, package in enumerate(packages):
    parent = parent_a if package_index < cut else parent_b
    inherited[package.id] = next(
        (
            (truck_index, placements[package.id])
            for truck_index, placements in enumerate(parent.placements)
            if placements[package.id] is not None
        ),
        None,
    )
\end{lstlisting}

Setelah mewarisi gen, implementasi membangun anak dari peta penempatan kosong. Untuk setiap paket yang diwarisi dalam keadaan termuat, operator lebih dahulu mencoba truk asalnya. Jika posisi dan orientasi asal tidak dapat dipertahankan, operator mencari posisi lain pada truk tersebut, kemudian mencoba truk lain. Paket yang gagal ditempatkan setelah semua percobaan tetap tidak dimuat.

Loop GA memakai implementasi generik \texttt{genetic\_algorithm}. Adapter armada menyediakan pembangkit populasi, crossover, mutasi, objective, dan validator. State awal tetap menjadi individu pertama dalam populasi. Populasi generasi berikutnya tidak memakai elitisme, sehingga individu terbaik dapat hilang dari generasi berikutnya. Loop GA tetap menyimpan solusi terbaik yang ditemukan untuk dikembalikan sebagai hasil akhir.

\subsubsection{Kontrak Pencarian, Masukan, dan Keluaran}

\texttt{search\_problem\_for\_state} memilih operasi berdasarkan tipe state. Masukan armada dapat memakai field JSON \texttt{trucks} untuk mencantumkan truk dengan dimensi dan kapasitas berbeda. Untuk data lama, field \texttt{truck} tunggal dapat direplikasi melalui argumen CLI \texttt{--truck-count}. Contoh konfigurasi armada heterogen ditampilkan berikut ini.
